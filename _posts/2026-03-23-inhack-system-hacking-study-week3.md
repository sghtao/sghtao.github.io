우선 리눅스는 지난 학기 F1tenth 프로젝트를 하면서 많이 다뤘기에 익숙한 환경이다. ROS2를 사용하기 위해 우분투를 썼던 기억을 되살려 리눅스를 공부해보자. 사실 리눅스를 써본 것도, 우분투 터미널에서 명령어 때리는 정도만 해봤지, 메모리 구조나 더 깊은 관점으로 공부해보지는 못했기 때문에 내용이 조금 생소하고 어려울 수 있을 것 같기는 하다. 이번 학기 빅데이터 시스템을 듣기도 하고 보안 공부를 이번 학기는 죽이되든 밥이되든 무조건 끝까지 해본다고 결심했으니, 끝까지 공부해보자.

## Linux Memory Layout
 
컴퓨터는 크게 CPU와 메모리로 구성되어 있다. CPU는 명령어와 메모리를 읽고 처리하여 그 연산 결과를 다시 메모리에 적재한다. CPU와 메모리는 밀접하게 연관되어 있기 때문에, 메모리 구조를 이해하는 것은 중요하다. 만약 공격자가 메모리를 악의적으로 조작할 수 있다면, 조작된 메모리 값에 의해 CPU가 잘못된 동작을 할 수 있다. 이를 유발하는 취약점을 메모리 오염(Memory Corruption) 취약점이라고 부른다.
 
리눅스에서 프로세스의 메모리는 크게 5가지 세그먼트로 구분한다. 세그먼트란 적재되는 데이터의 용도별로 메모리의 구획을 나눈 것이다. 각 세그먼트는 용도에 맞게 읽기(r), 쓰기(w), 실행(x) 권한이 부여되며, CPU는 해당 영역에 부여된 권한의 행위만 할 수 있다.
 
### 코드 세그먼트 Code Segment
 
실행 가능한 기계어 코드가 위치하는 영역으로, 텍스트 세그먼트(Text Segment)라고도 부른다. 읽기, 실행 권한이 주어진다. 쓰기 권한이 주어지면 취약점을 이용하여 프로그램의 코드가 수정될 수 있기 때문에 쓰기 권한은 주어지지 않는다. 어셈블리어에서는 `section .text`를 입력한 후에 어셈블리어를 입력하면 코드 세그먼트에 들어가게 된다.
 
### 데이터 세그먼트 Data Segment
 
컴파일 시점에 값이 정해진 전역 변수 및 전역 상수들이 위치한다. 읽기 권한이 주어진다. 쓰기 가능/불가능한 세그먼트로 다시 분류되는데, 쓰기가 가능한 세그먼트에는 전역 변수와 같이 프로그램이 실행되면서 값이 변할 수 있는 데이터들이 위치하고 이를 data 세그먼트라고 한다. 반면 쓰기가 불가능한 세그먼트에는 프로그램이 실행되면서 값이 변하면 안 되는 데이터들이 위치하며, 이를 rodata(read-only data) 세그먼트라고 부른다.
 
### BSS 세그먼트
 
Block Started By Symbol Segment로, 컴파일 시점에 값이 정해지지 않은 전역 변수가 위치하는 메모리 영역이다. 프로그램이 시작될 때 모두 0으로 초기화된다. 읽기, 쓰기 권한이 부여된다.
 
### 스택 세그먼트 Stack Segment
 
프로세스의 스택이 위치하는 영역으로 읽기, 쓰기 권한이 주어진다. 지역 변수와 매개변수, 함수의 리턴 주소가 들어간다. 함수가 호출될 때 할당되고, 반환될 때 해제된다. 높은 주소값에서 낮은 주소값으로 크기를 키운다.
 
### 힙 세그먼트 Heap Segment
 
힙 데이터가 위치하는 세그먼트로, 스택과 마찬가지로 실행 중에 동적으로 할당될 수 있다. 스택 세그먼트와 반대 방향으로 자라며, 낮은 주소값에서 높은 주소값으로 크기를 키운다. `malloc`, `new` 등을 통한 동적 할당 시 들어가는 영역이다. 일반적으로 읽기, 쓰기 권한이 주어진다.
 
## 레지스터
 
레지스터는 CPU 내부에 존재하는 아주 작고 기하급수적으로 빠른 기억 장치(메모리)이다. CPU와 구분된 메모리가 아니라, CPU 내부에 존재하는 메모리여서 CPU가 당장 작업하기 위해 들고 있는 손 정도로 이해하자.
 
CPU의 연산 속도는 메모리에서 데이터를 가져오는 속도보다 압도적으로 빠르다. 그래서 매번 연산을 할 때마다 CPU가 메모리에서 데이터를 가져와야 하면 병목이 생긴다. 따라서 CPU는 당장 연산에 필요한 데이터나 다음에 실행할 메모리 주소 등을 자신의 내부 공간인 레지스터에 임시로 저장해두고 초고속으로 명령을 처리한다.
 
다양한 레지스터가 존재하지만 아래 5가지는 익숙해져야 한다.
 
- `rip` (instruction pointer): CPU가 다음에 실행할 명령어의 주소를 가리키는 레지스터
- `rdi`: 리눅스에서 가장 첫 번째 인자가 들어가는 레지스터
- `rsi`: 리눅스에서 두 번째 인자가 들어가는 레지스터
- `rsp` (stack pointer): 현재 스택의 최상단 주소를 가리키는 레지스터
- `rbp` (base pointer): 현재 실행 중인 함수의 스택 프레임 시작 지점을 가리키는 레지스터
 
## x86 Assembly
 
어셈블리는 해커의 언어다.
 
어셈블리 언어(Assembly Language)와 어셈블러(Assembler). 개발자들이 어셈블리어로 코드를 작성하면 어셈블러는 컴퓨터가 이해할 수 있는 기계어로 코드를 치환한다. 어셈블리어는 컴퓨터 아키텍처별로 다른 문법을 가지고 있고, 같은 아키텍처에서도 어셈블러에 따라 다른 문법을 가질 수 있다. 대표적인 두 문법이 Intel 문법과 AT&T 문법이다. 팀장님께서도, 드림핵 강의에서도 Intel 문법을 기준으로 하니 Intel 문법을 익히자.
 
x64 어셈블리 언어의 문법 구조는 단순하다.
 
- 동사: 명령어 (Operation Code, Opcode)
- 목적어: 피연산자 (Operand)
 
피연산자는 해당 연산의 입력 값(레지스터, 상수, 메모리 주소 등)이 된다. 피연산자의 개수는 0개 혹은 그 이상이 될 수 있고, 명령어(동사)에 따라 다르다.
 
### 주요 명령어 (21개)
 
- 데이터 이동 (Data Transfer): `mov`, `lea`
- 산술 연산 (Arithmetic): `inc`, `dec`, `add`, `sub`
- 논리 연산 (Logical): `and`, `or`, `xor`, `not`
- 비교 (Comparison): `cmp`, `test`
- 분기 (Branch): `jmp`, `je`, `jg`
- 스택 (Stack): `push`, `pop`
- 프로시져 (Procedure): `call`, `ret`, `leave`
- 시스템 콜 (System call): `syscall`
 
### 피연산자의 종류
 
- 상수 (Immediate Value)
- 레지스터 (Register)
- 메모리 (Memory): `[]`로 둘러싸인 것으로 표현된다.
