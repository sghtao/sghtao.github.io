## 1. 도입

이번 주차에서 가장 주요하게 다루는 주제는 암호학, 특히 ECC(타원곡선 암호학)다.

ECC를 제대로 이해하면 다음 네 가지를 이해할 수 있다고 한다.

- 왜 개인키 하나만 잃어버리면 모든 게 끝나는지
- HD 지갑이 어떻게 수억 개의 주소를 안전하게 관리하는지
- ERC-20 토큰이나 NFT가 어떻게 내 것임을 증명하는지
- EVM 위에서 돌아가는 스마트 컨트랙트가 안전한 이유까지

암호학이라는 이름만 봐도 심리적 장벽이 생기는 건 사실이다. 하지만 이를 이해하는 것이 블록체인을 제대로 이해하는 데 핵심이라고 하니, 이번 온보딩 스터디를 계기로 정면으로 마주해보자.

## 2. 타원곡선 암호학 (ECC)

**Elliptic Curve Cryptography**. 이름이 타원이지만, 타원처럼 생긴 것은 아니다.

### 왜 '타원'이라는 이름이 붙었나

역사적 흐름을 따라가보면 이해가 된다.

1. 타원의 호 길이를 계산하기 위해 적분을 시도했다.
   - `∫ √(1 - k²sin²θ) dθ` — 이를 타원 적분(elliptic integral)이라고 한다.
2. 이 적분은 닫힌 형태로 풀리지 않는다.
3. 수학자들이 "그럼 이 적분의 역함수를 새로운 함수로 정의하자"고 했고, 이것이 타원 함수(elliptic function)다.
4. 이 타원 함수를 분석하다 보면 다음 관계식이 나온다.

```
y² = x³ + Ax + B   (Weierstrass 단축형)
```

이것이 바로 **타원 곡선(elliptic curve)**이다. 타원의 호 길이를 구하려다 만들어진 곡선이기 때문에 '타원'이라는 이름이 붙었다.

### 유한체(Finite Field) 위에서의 계산

블록체인에서는 실수 위의 곡선을 사용하지 않는다. 실수는 무한하고 정확한 계산이 불가능하기 때문이다. 대신 **유한체(Finite Field)** 위에서 계산한다.

아주 큰 소수 p로 나눈 나머지(mod p) 세계에서만 점이 존재하도록 제한하면, 곡선 위에 유한한 개수의 점만 존재하게 된다.

**왜 p가 소수여야 하는가?**

체(Field)가 되려면 사칙연산이 모두 잘 정의되어야 한다. 특히 나눗셈(역원)이 항상 존재해야 한다. p가 합성수이면 mod p에서 나눗셈이 불가능한 경우가 생긴다. ECC에서 이것이 치명적인 이유는, 타원곡선 위의 점 덧셈 공식 자체에 나눗셈이 들어있기 때문이다.

```
λ = (y₂ - y₁) / (x₂ - x₁)
```

p가 소수여야 mod p 세계에서 나눗셈이 항상 가능하고, 나눗셈이 가능해야 타원곡선 위의 연산이 성립한다.

### secp256k1

비트코인, 이더리움, 그리고 대부분의 주요 암호화폐는 **secp256k1**이라는 타원곡선을 사용한다.

- **sec**: Standards for Efficient Cryptography
- **p**: Prime field
- **256**: 256비트 키 길이
- **k1**: Koblitz curve 1번

방정식은 간단하다.

```
y² = x³ + 7 (mod p)
```

Weierstrass 단축형에서 A=0, B=7을 대입한 곡선이다. A=0인 Koblitz 곡선은 자기 자신으로 돌아오는 특별한 변환(endomorphism)이 존재해서, 스칼라 곱 계산이 일반 곡선보다 빠르다.

## 3. 개인키와 공개키

### 개인키 (Private Key)

개인키는 secp256k1 곡선 위에 존재하는 점의 총 개수인 n 범위 안에서 뽑은 **랜덤한 256비트 숫자**다. n은 그룹 차수(group order)라고 부르며, 2²⁵⁶에 매우 가까운 큰 소수다.

범위가 1~n-1인 이유는 다음과 같다.
- 0이면 공개키가 무한원점이 되어 의미가 없다.
- n 이상이면 곡선 위 점이 n개뿐이라 중복이 생긴다.

### 공개키 (Public Key)

```
공개키 = 개인키 × G
```

G는 secp256k1 위에 미리 정해진 생성점(Generator Point)이다. G는 누구나 알 수 있는 공개된 값이다. 여기서 `×`는 일반 숫자 곱셈이 아니라 **타원 곡선 위의 스칼라 곱**이다.

개인키를 알면 공개키를 아주 빠르게 구할 수 있다. 하지만 역연산 — 공개키를 보고 개인키를 구하는 것 — 은 **이산 로그 문제(ECDLP)**라고 하며, 현재 기술로는 수백~수억 년이 걸릴 정도로 풀기 어렵다.

공개키는 두 가지 형태가 있다.
- **압축형(Compressed)**: 33바이트
- **비압축형(Uncompressed)**: 65바이트

요즘은 압축형을 주로 사용한다.

### 이더리움 주소 생성 흐름

```
개인키 → (타원곡선 스칼라 곱, ×G) → 공개키 → (해시 함수) → 이더리움 주소
```

개인키와 생성점 G를 스칼라 곱하여 공개키를 계산하고, 이 공개키를 다시 해시해서 이더리움 주소가 만들어진다. 이것이 내 지갑의 소유권을 수학적으로 증명할 수 있는 이유다.

## 4. 지갑 (Wallet)

지갑은 단순히 암호화폐 잔고를 보여주는 앱이 아니다. ECC로 만든 개인키와 공개키를 안전하게 관리하고, 블록체인과 연결해서 돈을 주고받으며 스마트 컨트랙트를 사용하는 **출입구** 역할을 한다.

### Custodial vs Non-custodial

- **Custodial 지갑**: 거래소가 개인키를 대신 보관하는 수탁 형태. 업비트, 바이낸스 같은 CEX가 여기에 해당한다.
- **Non-custodial 지갑**: 내가 직접 개인키를 보관하는 형태. "Not your keys, not your coins."

### HD 지갑 (Hierarchical Deterministic Wallet)

예전 지갑은 10개의 주소를 사용하면 10개의 개인키를 모두 백업해야 했다. HD 지갑은 **하나의 시드 문구**만 있으면 여러 개의 개인키, 공개키, 주소를 자동으로 만들어 관리할 수 있다.

이 기술은 세 가지 표준으로 이루어진다.

- **BIP-39**: 시드 문구(Seed Phrase) — MetaMask를 처음 만들 때 나오는 영어 단어들. 이 시드 문구만 있으면 모든 개인키를 다시 만들 수 있다.
- **BIP-32**: 계층 구조로 키를 파생시키는 방법
- **BIP-44**: 어디에 어떤 키를 만들어야 하는지 규칙(경로)

시드 문구의 중요성은 아무리 강조해도 모자라다. 시드 문구를 잃으면 지갑에 접근할 방법이 영원히 사라진다.

**시드 문구 안전하게 보관하는 방법**
1. MetaMask 설치 후 시드 문구를 종이에 직접 적는다.
2. 종이를 사진 찍지 말고, 금고나 안전한 곳에 보관한다.
3. 누구에게도 알려주지 않는다.

## 5. 토큰 표준 — ERC-20, ERC-721, ERC-1155

이더리움 블록체인 위에서는 스마트 컨트랙트로 코인이나 NFT를 만들 수 있다. 하지만 마음대로 만들면 서로 호환이 안 된다. 그래서 미리 정해진 규칙이 있는데, 이를 **토큰 표준(Token Standard)**이라고 한다.

### ERC-20 — 대체 가능한 토큰

ERC-20은 **대체 가능(Fungible)** 한 토큰이다. 1,000원 지폐 하나와 다른 1,000원 지폐 하나는 완전히 똑같다. 비트코인, 이더리움, USDT, UNI 등이 모두 ERC-20 토큰이다.

ERC-20이 반드시 가져야 하는 6가지 핵심 함수:

| 함수 | 설명 |
|------|------|
| `totalSupply()` | 총 발행량 |
| `balanceOf(주소)` | 특정 주소의 잔액 |
| `transfer(받는사람, 금액)` | 직접 송금 |
| `approve(허락받을사람, 금액)` | 제3자에게 사용 허가 |
| `transferFrom(보낸사람, 받는사람, 금액)` | 허가받은 제3자가 대신 송금 |
| `allowance()` | 허가된 금액 조회 |

### ERC-721 — NFT

ERC-721은 **대체 불가능(Non-Fungible)** 한 토큰이다. 세상에 하나뿐인 그림, 사진, 게임 아이템, 부동산 증서 같은 개념이다. 하나하나가 고유한 ID를 가지고 있어서, 같은 컬렉션이라도 토큰마다 가치가 완전히 다를 수 있다.

### ERC-1155 — 복합 표준

ERC-1155는 ERC-20과 ERC-721을 합친 만능 표준이다.

- 같은 종류의 토큰은 대량으로 (ERC-20처럼)
- 특별한 아이템은 하나씩 (ERC-721처럼)
- 한 번에 여러 종류의 토큰을 관리할 수 있어 가스비도 절약된다.

요즘 게임이나 대규모 NFT 프로젝트에서 많이 사용된다.

이 세 가지 표준 덕분에 수십만 개의 토큰과 NFT가 이더리움 위에서 서로 호환되며 동작할 수 있다.

## 6. EVM 복습 — State Transition Function

지난 주차에 이더리움이 State Machine이라는 것을 배웠다. 이번 주차에서 이더리움 백서의 핵심 한 줄을 만났다.

```
APPLY(S, TX) → S'
```

- **S**: 현재 이더리움의 전체 상태 (모든 계정 잔고, 모든 스마트 컨트랙트 데이터)
- **TX**: 사용자가 보내는 트랜잭션
- **S'**: 트랜잭션이 처리된 새로운 상태

한 줄로 풀면: "현재 상태(S)에 트랜잭션(TX)을 적용하면 새로운 상태(S')가 된다. 그리고 모든 노드가 똑같은 새로운 상태를 가지도록 만든다."

이 한 문장이 이더리움 전체를 설명하는 핵심이다.

EVM에 누구나 스마트 컨트랙트를 올리고 실행할 수 있지만, 한 번 배포된 스마트 컨트랙트는 절대 수정하거나 지울 수 없다. 그리고 Gas가 존재하는 이유는 튜링 완전성 때문이다 — 무한 루프를 방지하기 위해 Gas라는 시스템이 존재한다는 것을 지난 주차에 배웠다.

## 7. 마무리

이번 주차에서 ECC를 처음 제대로 마주했다. 타원 적분에서 타원 함수, 타원 곡선으로 이어지는 흐름을 따라가다 보니 왜 이 이름이 붙었는지, 왜 소수여야 하는지, 왜 역연산이 불가능한지가 조금씩 연결됐다.

아직 이해하지 못한 부분들을 솔직하게 남겨둔다.

- 타원곡선 위의 점 덧셈 공식이 구체적으로 어떻게 동작하는지
- 스칼라 곱이 실제로 어떻게 계산되는지
- BIP-32의 키 파생 과정 (HMAC-SHA512 등)
- 스마트 컨트랙트 보안과 ECC의 연결 지점

앞으로 드림핵의 암호학 커리큘럼과 스마트 컨트랙트 보안까지 연결해서 공부해볼 예정이다. 조금씩.
