## 1. 도입

지난 주차에 비트코인의 기술적 기반을 처음으로 훑어봤다. 블록, 트랜잭션, 해시 함수, UTXO, PoW — 비트코인이 어떻게 신뢰 없이 작동하는지 그 구조를 조금이나마 감잡을 수 있었다.

이번 주차는 이더리움이다.

이더리움은 비트코인과 같은 블록체인 기반 시스템이지만, 목표가 다르다. 비트코인이 탈중앙화된 화폐 시스템을 만들고자 했다면, 이더리움은 그 위에서 어떤 프로그램이든 실행할 수 있는 플랫폼 — 흔히 'world computer' — 을 지향한다.

K-mooc 강의와 마스터링 이더리움을 공부하며 개념들을 정리했다.

## 2. 이더리움이란 무엇인가

이더리움은 오픈 소스, 블록체인 기술 기반의 스마트 컨트랙트를 실행하는 분산 컴퓨팅 플랫폼이다. 이더리움 플랫폼에는 ether라는 암호화폐가 존재하며, 비트코인과 마찬가지로 거래소에서 거래된다.

2013년 비탈릭 부테린이 백서를 작성했고, 2014년 ICO를 거쳐 2015년 런칭됐다. 비탈릭은 비트코인의 핵심 기술인 블록체인에 화폐 거래 기록뿐 아니라 계약서 등의 추가 정보를 기록할 수 있다는 점에 착안해 분산 네트워크를 구성했다.

비트코인과 이더리움의 주요 차이는 세 가지다.

- **Smart Contract** — 코드로 작성된 계약을 자동으로 실행
- **Turing-completeness** — 어떤 연산이든 처리할 수 있는 범용 연산 능력
- **Account-based model** — UTXO 대신 계정 잔액 기반의 상태 모델

### 이더리움이란?
이더리움은 흔히 ‘world computer’라고 묘사된다. 컴퓨터 과학적 관점에서 이더리움은 전역적으로 접근 가능한 단일 상태(singleton state)와 이 상태를 변경하는 이더리움 가상 머신(EVM)으로 구성된 결정론적인 상태 머신(state machine)이다. 즉, 공유된 상태를 가진 상태를 가진 트랜잭션 기반의 단일 머신(transactional singleton machine with shared-state)이며, 제네시스 상태에서 시작하여 트랜잭션을 실행함으로써 새로운 상태로 점진적으로 변화해 나가는 시스템으로 정의할 수 있다.


말이 어려우니 하나씩 살펴보자.

## 3. State Machine 개념 뜯어보기

### State란?

이더리움에서 **State(상태)**란, 특정 시점에서 전역적으로 합의된 네트워크의 전체 장부 — 즉 모든 계정 잔고, 스마트 컨트랙트 코드, 저장소 데이터를 담은 현재 스냅샷이다.

### Singleton State란?

**Singleton state(단일 상태)**에서 singleton이란, 전체 시스템이 완벽하게 동의하고 공유하는 단 하나의 유일한 상태(장부)를 가진다는 의미다. 단일 중앙 서버에 저장되는 게 아니라, 전 세계 수많은 노드의 로컬 하드드라이브에 각각 저장된다.

### State Machine이란?

**State machine(상태 머신)**은 genesis state에서 시작해, 트랜잭션이라는 입력을 실행함에 따라 점진적으로 새로운 상태로 변화해 나가는 모델이다.

### EVM이란?

각 노드에 State가 로컬로 저장되는데, 왜 EVM이라는 가상 머신이 필요할까?

**EVM(Ethereum Virtual Machine)**은 이더리움 네트워크에서 스마트 컨트랙트를 실행하는 스택 기반의 가상 머신이다. State 자체는 특정 시점의 정적 장부일 뿐이다. 전 세계 수많은 노드들이 각자 로컬 상태를 업데이트하면서도 모두가 완벽히 똑같은 결과에 도달하려면, 어떤 컴퓨터에서 실행하든 동일한 입력에 대해 항상 똑같은 결과를 보장하는 통제된 실행 환경이 필요하다. EVM이 이 역할을 수행한다.

**스택(Stack)이란?**

EVM이 스택 기반이라고 했는데, 스택이란 무엇인가?

스택은 LIFO(Last In First Out) 원리를 따르는 데이터 구조다. 가장 나중에 쌓인 원소가 가장 먼저 제거된다. push는 스택에 원소를 더하는 연산이고, pop은 스택에서 원소를 제거하는 연산이다.

![스택의 push와 pop](/assets/img/image-1.png)

> **State + EVM = State Machine**  
> 정보의 스냅샷인 State와, 트랜잭션이라는 입력이 들어왔을 때 이를 연산하고 기존 State를 새로운 State로 변화시키는 EVM이 결합하면 — 트랜잭션이 발생할 때마다 끊임없이 새로운 상태로 변화해 나가는 거대한 분산형 합의 상태 머신이 완성된다. 이것이 이더리움이다.

### 결정론적(Deterministic)이란?

결정론적 시스템이란, 동일한 초기 상태와 동일한 입력이 주어졌을 때, 언제 어디서 실행하든 항상 100% 똑같은 결과를 도출하는 시스템이다.

- **확률론적(Stochastic)**: 입력값을 넣으면 결과가 어떤 분포를 따른다.
- **비결정론적(Non-deterministic)**: 결과를 분포조차 정의할 수 없다.

이더리움은 전 세계 노드가 완벽히 동일한 단일 상태에 도달해야 하는 분산 합의 시스템이기 때문에, EVM 내에서 결과가 달라질 수 있는 모든 가능성을 철저히 배제한다. 만약 스마트 컨트랙트에 비결정론적 코드가 허용된다면, 수만 대의 컴퓨터가 각기 다른 결과를 내놓아 합의에 도달할 수 없을 것이다.

## 4. State와 이더리움 블록체인

State는 각 노드의 로컬 하드드라이브에 있는 데이터베이스(주로 Google의 LevelDB)에 저장된다.

이더리움의 전체 상태(World State)는 블록 안에 통째로 저장되지 않는다. 이더리움 블록체인은 직전 블록 헤더의 해시값인 `parentHash`를 해시 포인터로 삼아 꼬리를 물고 이어지는 연결 리스트(Linked List) 구조를 띤다. 블록 헤더에는 방대한 전체 상태 데이터 대신, 상태 트리의 가장 꼭대기 해시값인 32바이트의 `stateRoot`만을 기록한다.

트랜잭션이 발생해 누군가의 잔고나 데이터가 변경되면, 전체 상태 트리를 새로 복사하는 게 아니다. 변경된 부분의 트리 경로만 새롭게 업데이트되고, 나머지는 이전 블록의 포인터를 재사용해 그대로 참조한다.

결과적으로 블록체인은 transaction과 stateRoot를 체인 형태로 기록하는 거대한 일지 역할을 하고, 실제 원장 데이터는 각 노드의 로컬 DB에 효율적으로 나뉘어 저장된다.

## 5. State Bloat

State는 시간이 갈수록 너무 커지는 게 아닌가?

맞다. 이를 **State Bloat(상태 폭발)**이라고 한다.

이더리움의 State는 끊임없이 비대해지며, 이는 풀 노드 운영을 어렵게 만드는 심각한 단점이다. 2025년 기준 일반적인 풀 노드를 운영하려면 최소 2TB 이상의 NVMe SSD가 필요하고, 아카이브 노드는 12~15TB 이상을 요구한다.

데이터가 너무 무거워지면 일반 사용자가 노드를 운영하기 어려워지고, 소수의 기관만 노드를 운영하게 되어 탈중앙화가 훼손될 위험이 있다.

이더리움 개발진도 이 한계를 인지하고 있으며 구조적 해결책을 도입 중이다.

- **History Pruning**: 최신 상태 검증에 불필요한 오래된 데이터를 삭제하여 용량을 최적화한다.
- **The Purge & Statelessness**: 이더리움 2.0 로드맵의 일환으로, 노드가 과거 데이터를 저장해야 하는 부담을 줄이고, 미래에는 수 TB의 상태 데이터 없이도 블록의 정당성을 검증할 수 있는 구조로 전환할 계획이다.

## 6. Modified Merkle-Patricia Trie

이더리움이 State를 저장하는 자료구조가 바로 **Modified Merkle-Patricia Trie(MMPT)**다.

일반적인 머클 트리(비트코인에서 사용)는 고정된 거래 내역 검증에는 훌륭하지만, 데이터가 수시로 추가·삭제·변경되는 동적 데이터베이스 관리에는 비효율적이다. 이더리움의 State는 송금과 스마트 컨트랙트 실행에 따라 계정 잔고와 데이터가 끊임없이 변한다. 이더리움은 여기에 Patricia Trie(접두사 트리) 개념을 결합해 삽입·삭제·수정을 훨씬 빠르고 효율적으로 수행할 수 있도록 설계했다.

MMPT는 세 가지 노드 타입을 사용한다.

- **리프 노드(Leaf)**: 경로의 끝에 위치하며 실제 값(Value)을 포함한다.
- **확장 노드(Extension)**: 다수의 키가 같은 접두사를 공유할 때 이를 하나로 압축하는 최적화 노드다.
- **브랜치 노드(Branch)**: 경로가 갈라지는 분기점으로, 16진수 문자 16개와 종료 값 1개 총 17개의 항목을 가진다.

MMPT의 최상단 단일 값인 루트 해시(Root Hash)는 트리 내부의 모든 데이터에 암호학적으로 의존한다. 단 1비트라도 변조되면 최상단 해시값이 완전히 달라져 무결성을 보장한다. 또한 전체 데이터베이스를 다운로드하지 않고도 특정 계정의 잔고 유효성을 증명할 수 있어, 스마트폰에서도 실행 가능한 라이트 노드 구현을 가능케 한다.

## 7. 비트코인 vs 이더리움 — UTXO vs Account

### (1) UTXO 모델 (Bitcoin)

- **비유**: 현금(Cash) 지갑.
- **작동 방식**: 1만원을 가졌다면, 1천원짜리 10장일 수도, 5천원짜리 2장일 수도 있다. 만약 1만원짜리 지폐 1장만 가지고 있다면, 3천원짜리 커피를 사기 위해 1만원을 사용하고 거스름돈으로 7천원을 받는다. 이때 1만원 지폐(UTXO)는 완전히 소멸되고, 커피숍이 받은 3천원(UTXO)과 내가 받은 7천원(UTXO)이 새롭게 생성된다. UTXO는 부분적으로 사용할 수 없고, 항상 전액을 소비한 후 새로운 UTXO들로 쪼개진다.
- **데이터 구조**: 방향성 비순환 그래프(DAG, Directed Acyclic Graph). 거래들이 서로 꼬리를 물고 연결되어 있으며, 각 UTXO는 이전 거래의 출력(output)으로, 다음 거래의 입력(input)으로 연결된다.
- **표현**: `State = {UTXO1, UTXO2, UTXO3, ...}`

### (2) Account/Balance 모델 (Ethereum)

- **비유**: 체크카드 / 은행 계좌.
- **작동 방식**: 내 계좌에 10,000이라는 숫자가 적혀 있다. 3,000원을 사용하면, 10,000에서 3,000을 뺀 7,000이 남는다.
- **데이터 구조**: Merkle Patricia Trie. 지갑 주소(Address)를 Key로, 잔액(Balance)을 Value로 저장하는 Key-Value 매핑 구조.
- **표현**: `State → Transaction → State'(Update)`

## 8. 스마트 컨트랙트

스마트 컨트랙트는 EVM 내부에서 실행되는 컴퓨터 프로그램이다. 단순히 '이행해야 할 계약'이라기보다, 미리 정해진 코드를 실행하는 자율 에이전트(Autonomous Agent)에 가깝다.

일반 사용자의 계정(EOA, Externally Owned Account)과 달리 개인키가 없으며, 오직 자신이 가진 코드 로직에 의해서만 통제된다. 누군가 컨트랙트 주소로 트랜잭션을 보내면 코드가 실행되고, 내부 저장소를 읽고 쓰거나 다른 컨트랙트를 호출하고 이더를 송수신할 수 있다.

## 9. 튜링 완전성과 가스

### 튜링 완전성 (Turing Completeness)

비트코인의 스크립트 언어는 무한 루프를 허용하지 않는다(튜링 불완전). 반면 이더리움은 루프를 포함한 어떤 형태의 계산이든 처리할 수 있는 범용 컴퓨터의 성질을 가진다. 이를 **튜링 완전하다**고 한다.

그런데 여기서 치명적인 문제가 생긴다. 컴퓨터 과학의 난제인 **정지 문제(Halting Problem)** — 코드를 실제로 실행해보기 전에는 이 프로그램이 정상적으로 종료될지, 아니면 영원히 끝나지 않는 무한 루프에 빠질지 예측할 수 없다. 만약 해커가 무한 루프를 도는 스마트 컨트랙트를 배포한다면, 전 세계 노드가 이를 연산하느라 멈춰버리는 DoS 공격이 가능해진다.

### 가스 (Gas)

이 문제를 해결하기 위해 도입된 것이 **가스(Gas)**다. 가스는 연산의 미터기다.

EVM이 스마트 컨트랙트를 실행할 때, 더하기·곱하기·데이터 저장 등 모든 단일 명령어(Opcode)마다 미리 정해진 가스 비용이 청구된다. 트랜잭션을 보낼 때는 최대 가스 한도(gasLimit)를 설정해야 하고, 만약 코드가 무한 루프에 빠져 가스를 모두 소진(Out-of-Gas)하면 EVM은 즉시 연산을 강제 종료하고 State를 실행 이전으로 되돌린다. 단, 검증자의 연산에 대한 보상으로 수수료는 환불되지 않는다.

가스는 이더(Ether)로 구매해 지불하며, 연산이 정상적으로 끝나고 남은 가스는 발신자에게 환불된다.

## 10. DApp과 Web3

스마트 컨트랙트가 발전하면서 이더리움은 단순 블록체인을 넘어 거대한 애플리케이션 플랫폼으로 확장됐다.

**DApp(탈중앙화 애플리케이션)**은 블록체인 위에서 돌아가는 스마트 컨트랙트(백엔드 로직)와 사용자가 상호작용할 수 있는 웹 사용자 인터페이스(프론트엔드)가 결합된 형태를 의미한다.

**Web3**는 이더리움 공동 창시자 가빈 우드(Gavin Wood)가 제안한 개념으로, 특정 기업이 서버와 데이터를 소유하던 기존 웹(Web 2.0)에서 벗어나, P2P 프로토콜과 블록체인 인프라를 기반으로 구축된 탈중앙화된 웹 생태계를 지칭한다.

요약하면: 이더리움은 튜링 완전한 스마트 컨트랙트를 지원하고, 가스로 무한 루프 문제를 통제한다. 안전하게 동작하는 코드에 프론트엔드를 결합한 것이 DApp이며, 이러한 앱들이 모여 중앙 통제 없는 차세대 인터넷인 Web3를 형성한다.
